# 建築図面解析・設備設計支援システム

建築図面（CAD / PDF）を設備設計で利用可能な構造化データへ変換するための基盤ツール群です。

## 概要

```text
CAD/PDF（DXF・PDF・画像）
        ↓
  建築図面解析基盤
        ↓
 ┌──────┴────────┐
 ↓               ↓
部屋情報解析      図面差分比較
 ↓               ↓
部屋名・面積      建築変更箇所
 └──────┬────────┘
        ↓
   設備設計データ（換気計算・機器選定）
```

## 設計方針

- **アルゴリズム優先**: 座標計算・幾何演算は通常のアルゴリズムで処理し、AIは部屋名の意味判定など補助用途のみ
- **セキュリティ**: 建築図面データを外部AIサービスへ送信しない（ローカル処理を優先）
- **無料・オープンソース**: ezdxf, Shapely, PyMuPDF 等の OSS ライブラリを使用
- **拡張性**: 共通インターフェースで各エンジン（OCR・AI等）を差し替え可能な設計

## プロジェクト構成

```text
ArchitecturalDrawingAnalyzer/
├── core/                  # 共通基盤モジュール
│   ├── models/            # データモデル（Drawing, Room, Change, OCRResult）
│   ├── coordinate/        # 座標系変換（CAD ↔ PDF ↔ 画像 ↔ 共通mm座標）
│   ├── geometry/          # 幾何演算エンジン（Shapely ラッパー）
│   ├── parser/            # 図面パーサー（DXF, PDF, 画像）
│   ├── ocr/               # OCRエンジン（Tesseract, PaddleOCR, EasyOCR）
│   └── ai/                # AI補助エンジン（ローカル・無効化可能）
├── apps/                  # 各アプリケーション
│   ├── room_analyzer/     # App 01: 建築図面解析
│   └── drawing_diff/      # App 02: 図面差分比較
├── data/                  # プロジェクトデータ（.gitignore 除外）
├── tests/                 # ユニットテスト
├── docs/                  # 開発ドキュメント・開発ログ
└── requirements.txt
```

## セットアップ

### 必要要件

- Python 3.9 以上
- Windows 10/11

### インストール

```powershell
# 仮想環境の作成とアクティベート
python -m venv venv
.\venv\Scripts\Activate.ps1

# 依存ライブラリのインストール
# ※フォルダパスに絵文字が含まれる場合は以下の環境変数設定が必要
$env:PYTHONIOENCODING="utf-8"
pip install -r requirements.txt
```

### アプリケーションの起動

```powershell
# Python環境から直接起動
$env:PYTHONIOENCODING="utf-8"
.\venv\Scripts\python.exe main.py

# または生成済みEXE（スタンドアロン）から起動
.\dist\ArchitecturalDrawingAnalyzer\ArchitecturalDrawingAnalyzer.exe
```

### EXEのビルド

```powershell
$env:PYTHONIOENCODING="utf-8"
.\venv\Scripts\python.exe scripts/build_exe.py
```

### テスト実行

```powershell
$env:PYTHONIOENCODING="utf-8"
.\venv\Scripts\pytest -v
```

## 現在の試作機能（DXF部屋候補検出）

- DXFを読み込み、レイヤー表示・図形選択・拡大縮小を行えます。カーソル座標の単位表示も、図面から判定した座標単位（mm・cm・m・in・ft）に合わせます。
- ツールバーの「部屋候補を検出」で、閉じた直線ポリラインとLINE要素から閉領域候補を抽出します。候補領域内に文字要素が1つだけあり、他候補との重複がなければ、その文字を部屋名として暫定的に紐付けます。
- LINE要素の端点は、既定では `Drawing.units` に基づき実寸換算で約 1 mm 相当以内の隙間を接続候補として扱います。許容値を明示指定する場合は図面座標単位で指定します。DXFの `$INSUNITS` がインチ・フィート・mm・cm・mを示す場合はその単位を読み取り、明示的な `units` 指定があればそちらを優先します。単位未設定または未対応の値は従来どおりmmとして扱い、読み取った単位とその根拠をメタデータに記録します。図面側の単位設定自体が誤っている場合は正しい面積にならないため、実図面での確認が必要です。許容値が大きいと、本来別の線を誤接続する可能性があります。
- ポリラインと線分から同一形状が検出された場合、重複候補を抑制します。線分で囲まれた領域が入れ子になり、壁厚やシャフト等によって穴あきポリゴンが生じるケースは、単一の境界線しか保持できない現状のデータ形式では面積と境界が食い違うため、候補を保守的に除外します。
- 部屋名の紐付けは文字の挿入点が領域内にあり、候補内の文字が1つだけの場合に限る保守的な初期処理です。複数文字・候補の重なり・数値のみの文字は自動判定しません。文字の意味理解や高度な曖昧性解消は未実装です。
- 結果は暫定面積候補です。二重線壁の壁芯、複雑な壁の判断、実図面での精度保証は未実装です。設計値として直接使用せず、必ず図面と照合してください。
- 図面処理はローカルで実行する方針で、外部AIサービスへの図面送信は行いません。
